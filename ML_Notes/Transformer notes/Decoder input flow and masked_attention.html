Section 01
সহজ ভাষায় পরিচিতি — Intuition

এই Concept কী এবং কেন দরকার?

কল্পনা করো তুমি একজন অনুবাদক। তোমার কাছে একটি ইংরেজি বই দেওয়া হলো এবং বলা হলো বাংলায় অনুবাদ করো। তুমি যখন প্রথম শব্দটি অনুবাদ করছ, তখন তুমি কি বইয়ের পরের শব্দ দেখছ? অবশ্যই না — তুমি শুধু এখন পর্যন্ত যা পড়েছ তার ভিত্তিতেই পরের শব্দটি লিখছ।

ঠিক এই ধারণাটাই হলো Masked Multi-Head Attention-এর মূল ভিত্তি। Transformer-এর Decoder যখন Output তৈরি করে, তখন সে এমনভাবে কাজ করে যেন সে ভবিষ্যৎ দেখতে পাচ্ছে না — শুধু অতীত ও বর্তমান দেখতে পাচ্ছে।

🍳 রান্নাঘরের উদাহরণ

ধরো তুমি রান্না করছ। রেসিপিতে লেখা আছে: "প্রথমে পেঁয়াজ কাটো, তারপর তেল দাও, তারপর মশলা দাও।" তুমি কি মশলা দেওয়ার আগেই তেল দিতে পারবে? না! কারণ প্রতিটি ধাপ আগের ধাপের উপর নির্ভরশীল। Language Generation-ও ঠিক এরকম — প্রতিটি শব্দ আগের শব্দগুলোর উপর নির্ভর করে।

এটি কোন সমস্যা সমাধান করে?

Transformer-এর Decoder-কে দুটো বিপরীত চাহিদা পূরণ করতে হয়:

❌ সমস্যা ১ — Slow Training
🔴একটা একটা করে Token প্রসেস করলে Training অনেক ধীর হয়
🔴৩০০ শব্দের Paragraph হলে ৩০১ বার একই Operation চালাতে হয়
🔴লক্ষ লক্ষ Training Data থাকলে এটি অকল্পনীয় ধীর
❌ সমস্যা ২ — Data Leakage
🔴সব Token একসাথে দিলে Current Token ভবিষ্যতের Token দেখে ফেলে
🔴Training-এ চুরি করা তথ্য দিয়ে Prediction করা হয়
🔴Real Prediction-এ ভবিষ্যত Token কখনো পাওয়া যায় না
✅ Masked Attention-এর সমাধান

একসাথে সব Token Process করো (Fast Training) — কিন্তু Current Token কে ভবিষ্যতের Token দেখতে দিও না (No Data Leakage)। এই দুটো লক্ষ্য একই সাথে অর্জন করাই হলো Masking-এর কাজ।

Encoder বনাম Decoder — যাত্রার মাঝামাঝিতে

Transformer Architecture-কে দুটো বড় অংশে ভাগ করা যায়। ইতিমধ্যে Encoder সম্পূর্ণ পড়া শেষ। এখন Decoder পড়ার পালা।

✅ Encoder — সম্পূর্ণ পড়া (৫০%)

• Self Attention মেকানিজম

• Multi-Head Attention

• Positional Encoding

• Add & Norm Layer

• Feed Forward Layer

• পুরো Encoder Architecture

⏳ Decoder — এখন পড়ছি (৫০%)

• Masked Multi-Head Attention ← আজকের বিষয়

• Cross Attention (Encoder থেকে ২টি Arrow আসে)

• Decoder-এর বাকি সব Block (Encoder থেকে Repeat)

• পুরো Decoder Architecture (পরের ভিডিওতে)

💡 Decoder-এ নতুন কী আছে?

"Mask" শব্দটা — এটাই Decoder-কে Encoder থেকে আলাদা করে। এছাড়া Cross Attention যেখানে Decoder থেকে ১টি Arrow এবং Encoder থেকে ২টি Arrow আসে — এটাও নতুন। বাকি সব কিছু Encoder-এর মতোই Repeat।

Section 03
মূল সেন্টেন্স ও Autoregressive কী?

এই পুরো Concept বোঝার চাবিকাঠি হলো একটি বাক্য:

"The Transformer Decoder is an Autoregressive model at Inference time, and Non-Autoregressive at Training time."

Inference কী?

Inference মানে সহজ কথায় Prediction। যখন তুমি ট্রেনড মডেলকে দিয়ে কোনো কিছু প্রেডিক্ট করাচ্ছ — সেটাই Inference। এটাকে Real-World Use বলা যায়।

Autoregressive মডেল কী?

এই ধারণাটি মূলত Economics-এর, তারপর Time Series-এ এসেছে। Deep Learning-এর Context-এ:

সংজ্ঞা — Autoregressive Model

"Autoregressive models are a class of models that generate data points in a sequence by conditioning each new data point on the previously generated points."

সহজ কথায়: প্রতিটি নতুন ডেটা তৈরি করতে আগের ডেটার সাহায্য নেওয়া হয়।

📈 Stock Market উদাহরণ

বু
বুধবার — Stock = ২৯
মডেল বুধবারের Stock Value প্রেডিক্ট করেছে: ২৯
বৃ
বৃহস্পতিবার — Stock = ৩০
বুধবারের ২৯-এর উপর নির্ভর করে বৃহস্পতির মান প্রেডিক্ট করা হলো: ৩০

শুক্রবার — বুধ (২৯) + বৃহস্পতি (৩০) দেখে প্রেডিক্ট
এটাই Autoregressive — পূর্ববর্তী Output-এর উপর Condition করে নতুন Output তৈরি

কেন NLP মডেলগুলো Autoregressive হতে বাধ্য?

একসাথে সব শব্দ Generate করা সম্ভব নয়। কারণ — পরের শব্দ আগের শব্দের উপর নির্ভর করে। "মৈ বঢ়িয়া হূঁ" লিখতে হলে "মৈ" না লিখে "বঢ়িয়া" কোথা থেকে আসবে?

⚠️ Parallel Generation সম্ভব নয়

Sequential data-এর সবচেয়ে মৌলিক বৈশিষ্ট্য হলো — আগের জিনিস না আসলে পরেরটা জেনারেট করা যায় না। তাই Language Translation, Text Generation, Text Summarization — সব Sequential Task-এ Autoregressive Model ছাড়া কোনো বিকল্প নেই।

Section 04
Inference-এ Autoregressive — ধাপে ধাপে

মনে করো আমাদের কাজ: "I am fine" → হিন্দিতে অনুবাদ = "মৈ বঢ়িয়া হূঁ"

মডেল ট্রেন করা হয়ে গেছে। এখন Inference (Prediction) দেখি:

Step 1 — Encoder Input
"I", "am", "fine" — তিনটি শব্দ Encoder-এ ঢোকে। Encoder পুরো ইংরেজি সেন্টেন্স Parallel-এ প্রসেস করে (Self Attention ব্যবহার করে)। প্রতিটি শব্দের জন্য একটি Vector তৈরি হয়।
Step 2 — Decoder শুরু (START Token)
Encoder-এর Output + একটি Special "START" Token নিয়ে Decoder কাজ শুরু করে। এই দুই ইনপুটের ভিত্তিতে Decoder প্রথম শব্দ প্রেডিক্ট করে: "মৈ"
Step 3 — দ্বিতীয় Token (গলতি হলেও চলে)
Encoder Output + "মৈ" → Decoder পরবর্তী শব্দ প্রেডিক্ট করে। ধরো মডেল ভুল করে "ঘটিয়া" দিয়েছে (সঠিক হওয়া উচিত ছিল "বঢ়িয়া")। Inference-এ এটা নিয়ে চিন্তা নেই, সামনে এগিয়ে যাই।
Step 4 — তৃতীয় Token
Encoder Output + "মৈ" + "ঘটিয়া" → Decoder পরের শব্দ দেয়: "হূঁ" (সঠিক)
Step 5 — END Token
Encoder Output + "মৈ ঘটিয়া হূঁ" → Decoder দেয় END Token → Translation শেষ। Final Output: "মৈ ঘটিয়া হূঁ" (বদলে "মৈ বঢ়িয়া হূঁ" হওয়া উচিত ছিল — মডেল মাঝে ভুল করেছে।)
🔑 মূল পর্যবেক্ষণ

Inference-এ প্রতিটি Step-এ আগের Step-এর Output ব্যবহার করতেই হবে। এটা এড়ানোর কোনো উপায় নেই। তাই Inference সবসময় Autoregressive (Sequential)। এখানে কোনো Parallel Processing সম্ভব নয়।

Section 05
Teacher Forcing ও Training প্রক্রিয়া

Training Data ধরা যাক: "How are you?" → "আপ কৈসে হৈঁ"

ধরো আমরা এখনও পুরনো পদ্ধতি (Autoregressive Training) ব্যবহার করছি:

ধাপ ১ — Encoder Processing
"How", "are", "you" → Encoder → Context Vectors তৈরি। এই Vectors Decoder-এ পাঠানো হয়।
ধাপ ২ — Decoder প্রথম Token
START Token + Encoder Output → Decoder দেয় "তুম" (কিন্তু সঠিক হওয়া উচিত ছিল "আপ")
ধাপ ৩ — Teacher Forcing!
Decoder "তুম" দিয়েছে, কিন্তু পরের Step-এ "তুম" ইনপুট হিসেবে দেওয়া হয় না। বরং Dataset থেকে সঠিক শব্দ "আপ" নেওয়া হয়। এটাই Teacher Forcing। "শিক্ষক জোর করে সঠিক উত্তর বলে দিচ্ছেন।"
ধাপ ৪ — Loss Calculation
আসা উচিত ছিল "আপ কৈসে হৈঁ" — এসেছে "তুম কৈসে থে"। Loss Function দিয়ে পার্থক্য মেপে Backpropagation চালাও এবং Weights আপডেট করো।
💡 Teacher Forcing-এর সুবিধা

Training-এ পরের Step-এর Input সবসময় Dataset থেকে নেওয়া হয় — আগের Step-এর Output থেকে নয়। এর মানে হলো — প্রতিটি Step একে অপরের উপর নির্ভরশীল নয়। তাহলে কি সব Steps একসাথে চালানো যায়? হ্যাঁ! কিন্তু একটা বিশাল সমস্যা আছে...

Data Leakage কেন সমস্যা?

ধরো Sentence: "আপ কৈসে হৈঁ" — সব Token একসাথে Self Attention-এ দেওয়া হলো।

"আপ"-এর Contextual Embedding তৈরি করতে:

আপ-এর Contextual Embedding (ভুল পদ্ধতি)
C(আপ) = 0.8 × E(আপ) + 0.1 × E(কৈসে) + 0.1 × E(হৈঁ)
🚨 সমস্যা!

যখন "আপ" লেখা হয়েছিল, তখন কি "কৈসে" বা "হৈঁ" ছিল? না। তাহলে "আপ"-এর Embedding হিসাব করতে "কৈসে" এবং "হৈঁ"-এর Value ব্যবহার করা কীভাবে সঠিক হবে?

এটাই Data Leakage — Training-এ মডেলকে ভবিষ্যতের তথ্য দিয়ে দেওয়া, যা Inference-এ পাওয়া যাবে না। মডেল Training Data-তে ভালো Result দেবে, কিন্তু Real World-এ ব্যর্থ হবে।

Token Training-এ পায় Inference-এ পায় সমস্যা?
আপ আপ + কৈসে + হৈঁ শুধু আপ 🚨 Leakage
কৈসে আপ + কৈসে + হৈঁ আপ + কৈসে 🚨 Leakage
হৈঁ আপ + কৈসে + হৈঁ আপ + কৈসে + হৈঁ ✅ ঠিক আছে

লক্ষ্য করো — শুধু শেষ Token-এ কোনো সমস্যা নেই। বাকি সব Token-এ Data Leakage ঘটছে। এই সমস্যার সমাধানই হলো Masking।

Section 07
Self Attention-এর ভেতরের কাজ

Masking বোঝার আগে Self Attention-এর প্রতিটি ধাপ রিভিউ করা দরকার — কারণ এর ভেতরেই Masking-এর সমাধান লুকিয়ে আছে।

উদাহরণ: "আপ কৈসে হৈঁ" — এই তিনটি শব্দ Self Attention-এ পাঠানো হবে।

Step 1 — Embedding তৈরি

প্রতিটি শব্দকে সরাসরি মডেলে দেওয়া যায় না। আগে প্রতিটি শব্দকে Embedding Layer দিয়ে Vector-এ রূপান্তর করতে হয়।

Embedding Creation
  শব্দ        Embedding Layer     Embedding Vector

  "আপ"   ──────────────────→   E(আপ)   = [0.2, 0.8, -0.3, ...]
  "কৈসে" ──────────────────→   E(কৈসে) = [0.5, -0.1, 0.7, ...]
  "হৈঁ"  ──────────────────→   E(হৈঁ)  = [-0.2, 0.4, 0.9, ...]

Step 2 — Query, Key, Value তৈরি

Self Attention Block-এ ৩টি Weight Matrix আছে: W_Q, W_K, W_V। প্রতিটি শব্দের Embedding এই তিনটি Matrix-এর সাথে Dot Product করলে পাওয়া যায় Query (q), Key (k), Value (v) ভেক্টর।

Q, K, V Calculation
  E(আপ)   × W_Q = q_আপ    E(আপ)   × W_K = k_আপ    E(আপ)   × W_V = v_আপ
  E(কৈসে) × W_Q = q_কৈসে  E(কৈসে) × W_K = k_কৈসে  E(কৈসে) × W_V = v_কৈসে
  E(হৈঁ)  × W_Q = q_হৈঁ   E(হৈঁ)  × W_K = k_হৈঁ   E(হৈঁ)  × W_V = v_হৈঁ

  সব Q ভেক্টর মিলিয়ে → Q Matrix
  সব K ভেক্টর মিলিয়ে → K Matrix
  সব V ভেক্টর মিলিয়ে → V Matrix

Step 3 — Attention Score তৈরি

Q এবং K Matrix-এর Dot Product করলে একটি Attention Score Matrix পাওয়া যায়। এরপর স্কেলিং ও Softmax প্রয়োগ করা হয়।

Scaled Dot-Product Attention
Attention(Q, K, V) = Softmax( Q·Kᵀ / √d_k ) · V যেখানে d_k = Key Vector-এর Dimension
Attention Score Matrix (Softmax-এর পরে)
                আপ        কৈসে      হৈঁ
  আপ   │  w11=0.8  w12=0.1  w13=0.1  │
  কৈসে │  w21=0.15 w22=0.75 w23=0.1  │
  হৈঁ  │  w31=0.1  w32=0.2  w33=0.7  │

  লাল = সমস্যাজনক (Future Token দেখছে)
  হলুদ = নিজের Contribution
  নীল = অতীত Token থেকে (ঠিক আছে)

Step 4 — Contextual Embedding তৈরি

এই Weight Matrix দিয়ে Value Vectors-কে Weighted Sum করলে প্রতিটি শব্দের Contextual Embedding পাওয়া যায়:

Contextual Embedding Calculation
C(আপ) = w11×v_আপ + w12×v_কৈসে + w13×v_হৈঁ ← এই দুটো থাকা উচিত নয়! C(কৈসে) = w21×v_আপ + w22×v_কৈসে + w23×v_হৈঁ ← এটা থাকা উচিত নয়! C(হৈঁ) = w31×v_আপ + w32×v_কৈসে + w33×v_হৈঁ ← এটা সঠিক ✅
🚨 সমস্যার কেন্দ্র

"আপ"-এর Contextual Embedding তৈরিতে "কৈসে" ও "হৈঁ"-এর Contribution থাকছে। কিন্তু যখন "আপ" লেখা হয়েছিল, তখন এই শব্দগুলো ছিল না! এই w12, w13, w23 — তিনটি Weight-কে Zero করতে পারলেই সমস্যা সমাধান।

Section 08
Masking — সমস্যার সমাধান

w12, w13, w23 কে Zero করার উপায় কী? এখানেই আসে Masking-এর কৌশল।

Mask Matrix তৈরি করো

Softmax চালানোর আগের Scaled Score Matrix-এর সাথে একই Dimension-এর একটি Mask Matrix তৈরি করো। যেখানে যেখানে Value Zero করতে চাই, সেখানে −∞ (Minus Infinity) বসাও।

Mask Matrix
                আপ      কৈসে    হৈঁ
  আপ   │    0      -∞      -∞   │  ← আপ শুধু নিজেকে দেখতে পাবে
  কৈসে │    0       0      -∞   │  ← কৈসে, আপ ও নিজেকে দেখতে পাবে
  হৈঁ  │    0       0       0   │  ← হৈঁ, সবাইকে দেখতে পাবে

Mask যোগ করো Score-এ

Score Matrix + Mask Matrix
  Score Matrix         Mask Matrix          Result Matrix
  ┌─────────────┐   ┌─────────────┐    ┌─────────────────┐
  │  s11  s12  s13│ + │  0   -∞   -∞│  = │  s11   -∞    -∞  │
  │  s21  s22  s23│   │  0    0   -∞│    │  s21   s22   -∞  │
  │  s31  s32  s33│   │  0    0    0│    │  s31   s32   s33 │
  └─────────────┘   └─────────────┘    └─────────────────┘

Softmax চালাও

✨ Softmax-এর জাদু

Softmax(-∞) = 0 — এটা গণিতের একটি মৌলিক সত্য। যেখানে −∞ আছে, সেখানে Softmax প্রয়োগ করলে 0 পাওয়া যায়। ফলে সেই Weight গুলো শূন্য হয়ে যায়।

Softmax-এর পরে — Final Weight Matrix
                আপ      কৈসে    হৈঁ
  আপ   │   1.0     0.0     0.0  │  ← শুধু নিজের Value ব্যবহার
  কৈসে │   0.15    0.85    0.0  │  ← হৈঁ-এর Value শূন্য হয়ে গেছে
  হৈঁ  │   0.1     0.2     0.7  │  ← সব Value ব্যবহার করতে পারে

  সবুজ = শূন্য হয়ে গেছে (Data Leakage বন্ধ)
  হলুদ = বৈধ Contribution (অতীত ও বর্তমান)

এখন Contextual Embedding সঠিক!

Masked Self Attention — সঠিক ফলাফল
C(আপ) = 1.0 × v_আপ + 0.0 × v_কৈসে + 0.0 × v_হৈঁ = শুধু নিজের Value ব্যবহার ✅ (ভবিষ্যত দেখে না) C(কৈসে) = 0.15 × v_আপ + 0.85 × v_কৈসে + 0.0 × v_হৈঁ = অতীত (আপ) ও বর্তমান (কৈসে) ব্যবহার ✅ C(হৈঁ) = 0.1 × v_আপ + 0.2 × v_কৈসে + 0.7 × v_হৈঁ = সব Token ব্যবহার করতে পারে ✅

Lower Triangular Mask Pattern

Section 10
পূর্ণ সারসংক্ষেপ

পুরো Journey এক নজরে

১
Transformer Decoder → Autoregressive at Inference
Inference-এ প্রতিটি Output Token আগের Output Token-এর উপর নির্ভর করে। এটা Mandatory — Sequential Data-এ এর কোনো বিকল্প নেই।
২
Training → Teacher Forcing ব্যবহার
Training-এ পরের Step-এর Input সবসময় Dataset থেকে নেওয়া হয়। আগের Step কী Output দিল তা বিবেচনা করা হয় না।
৩
Parallel Training চাই, কিন্তু Data Leakage বন্ধ করতে হবে
Teacher Forcing-এর কারণে সব Steps Independent। Parallel Processing সম্ভব। কিন্তু সরাসরি Parallel করলে Current Token ভবিষ্যতের Token দেখে ফেলে → Data Leakage।
৪
Self Attention-এর Weight Matrix-এ সমস্যা
w12, w13, w23 এই Weight-গুলো ভবিষ্যতের Token-এর Contribution রাখছে। এদের Zero করতে হবে।
৫
Masking — Lower Triangular Mask দিয়ে সমাধান
Softmax-এর আগে Score Matrix-এ Mask যোগ করো। ভবিষ্যৎ Position-এ −∞ বসাও। Softmax(-∞) = 0 হয়। ফলে ভবিষ্যৎ Token-এর Contribution শূন্য।
৬
Best of Both Worlds — Fast + Correct
এখন Training Parallel (Fast) + Data Leakage নেই (Correct)। Inference এখনও Autoregressive (Mandatory)। Training Non-Autoregressive + Masked = Perfect।
মূল ধারণাগুলো
Autoregressive = পূর্ববর্তী Output-এর উপর নির্ভর Teacher Forcing = Dataset থেকে সঠিক Input দেওয়া Masking = ভবিষ্যৎ Token লুকানো Data Leakage = Training-এ চুরির তথ্য Non-Autoregressive = Parallel Processing

"Masked Self Attention আমাদের দেয় Training-এর গতি (Parallel Processing) এবং Inference-এর সততা (No Future Token Access) — একই সাথে। এটাই এই Mechanism-এর সৌন্দর্য।"

🔮 পরবর্তী কী?

Masked Multi-Head Attention বোঝা হয়ে গেছে — এটা Decoder-এর প্রথম Building Block। পরবর্তীতে আসবে Cross Attention (Encoder থেকে ২টি Arrow, Decoder থেকে ১টি Arrow) এবং তারপর পুরো Decoder Architecture এক ভিডিওতে।

❓
প্রশ্নোত্তর সিরিজ — গভীর বিশ্লেষণ

Decoder-এ Vector কি Parallel যায় নাকি Sequential?

এই প্রশ্নটির উত্তর নির্ভর করে Training নাকি Inference — সেটার উপর। দুটো ক্ষেত্রে আচরণ সম্পূর্ণ আলাদা।

🚀 Training-এর সময় → Parallel

Training-এ Teacher Forcing ব্যবহার করা হয় এবং Masking থাকে, তাই সব Vector একসাথে Decoder-এ পাঠানো যায়। আগের output-এর জন্য অপেক্ষা করতে হয় না।

🐢 Inference-এর সময় → Sequential

Inference-এ সঠিক উত্তর আমাদের কাছে নেই। তাই মডেলের নিজের output-ই পরের step-এর input হয়। এটা Autoregressive Loop।

🔑 গুরুত্বপূর্ণ প্রশ্ন: প্রথম output বের হলেই কি Backpropagation হয়?

না। কখনোই একটি মাত্র শব্দ বের হওয়ার সাথে সাথে Weight Update হয় না। পুরো প্রক্রিয়াটি এভাবে কাজ করে:

  1. পুরো Sentence-এর সব output আগে বের হয়
  2. সবগুলো output-এর Loss আলাদা আলাদা calculate হয়
  3. সব Loss যোগ করে একটি Total Loss বের করা হয়
  4. এই Total Loss-এর উপর ভিত্তি করে মাত্র ১ বার Backpropagation চলে
  5. সব Weight একসাথে Update হয়

Teacher Forcing — Loss কীভাবে Calculate হয়?

Teacher Forcing মানে input সঠিক দেওয়া। কিন্তু তাহলে কি Loss হওয়ার সুযোগ থাকে? — হ্যাঁ, কারণ Loss হিসাব হয় Output-এর উপর, Input-এর উপর নয়।

⚠️ সবচেয়ে বড় ভুল ধারণা

Teacher Forcing মানে মডেলের ভুল "ঠিক করে দেওয়া" নয়। এটা শুধু পরের step-এ সঠিক ইনপুট দেয়। মডেল আউটপুটে যে ভুল করে, সেটার Loss ঠিকই হিসাব হয়।

১
Input: [START] → Output: "তুমি" ❌

হওয়া উচিত ছিল "আমি"। Loss 1 = distance("তুমি", "আমি") হিসাব হলো এবং মেমোরিতে রাখা হলো।

২
Teacher Forcing: Input = "আমি" (Dataset থেকে, "তুমি" নয়!)

মডেল "তুমি" বললেও আমরা পরের step-এ Dataset থেকে সঠিক "আমি" input দিই। এতে Error Accumulation বন্ধ হয়।

৩
Input: "আমি" → Output: "খারাপ" ❌

হওয়া উচিত ছিল "ভালো"। Loss 2 = distance("খারাপ", "ভালো") হিসাব হলো।

৪
Input: "ভালো" → Output: "আছি" ✓

এবার সঠিক! Loss 3 = 0 (বা খুব কম)।

৫
Total Loss → Backpropagation → Weight Update

Total Loss = Loss 1 + Loss 2 + Loss 3। এই একটি সংখ্যার উপর ভিত্তি করে ১ বার Backpropagation, তারপর Weight Update।

Inference বিশ্লেষণ

Real-time Prediction-এ Sequential Loop কীভাবে কাজ করে

Inference-এ আমাদের কাছে কোনো সঠিক উত্তর নেই। তাই Teacher Forcing সম্ভব নয়। মডেল নিজের output দিয়েই পরের step-এ এগোয়।

❓ Inference-এ কি Masking লাগে?

না। Inference-এ Masking-এর প্রয়োজন নেই। কারণ ভবিষ্যতের শব্দগুলো তখনো তৈরিই হয়নি — চুরি করে দেখার কোনো সুযোগই নেই!

INFERENCE TIME — Autoregressive Loop: ════════════════════════════════════════════════════════════════ (Target: "আমি ভালো আছি" — কিন্তু মডেল এটা জানে না) Step 1: Decoder Input: [START] Encoder Output: → (source sentence context, fixed) ───────────────────────────────────────── Decoder Predicts: "আমি" ✓ → "আমি" এখন input-এ যোগ হলো Step 2: Decoder Input: [START] → "আমি" Encoder Output: → (same, unchanged) ───────────────────────────────────────── Decoder Predicts: "ভালো" ✓ → "ভালো" এখন input-এ যোগ হলো Step 3: Decoder Input: [START] → "আমি" → "ভালো" Encoder Output: → (same, unchanged) ───────────────────────────────────────── Decoder Predicts: "আছি" ✓ → "আছি" এখন input-এ যোগ হলো Step 4: Decoder Input: [START] → "আমি" → "ভালো" → "আছি" Decoder Predicts: [END] ───────────────────────────────────────── ✅ [END] Token পেলেই Loop বন্ধ! Final Output: "আমি ভালো আছি" ⚠️ এই Loop শুধু DECODER-এ চলে। ENCODER একবারই (Parallel) কাজ করে — তারপর চুপ।
🏗️ Encoder-এর কাজ (No Loop)

Encoder শুধু একবার পুরো source sentence Parallel-এ process করে। তারপর তার কাজ শেষ। সে Decoder-কে context দেয় এবং চুপ থাকে।

🔄 Decoder-এর কাজ (Loop!)

Decoder-ই একমাত্র অংশ যেখানে Inference-এ Autoregressive Loop চলে। প্রতি iteration-এ একটি নতুন word তৈরি হয়, [END] আসা পর্যন্ত।

Cross-Attention — Encoder ও Decoder-এর সংযোগ

Masked Self-Attention-এর পরে Decoder-এর দ্বিতীয় বড় Block হলো Cross-Attention (Encoder-Decoder Attention)। এখানে Encoder ও Decoder প্রথমবার সরাসরি "কথা বলে"।

🤔 Cross-Attention কেন দরকার?

Masked Self-Attention-এ Decoder শুধু নিজের তৈরি শব্দগুলো দেখে। কিন্তু সে জানে না Source sentence কী ছিল! Cross-Attention-এ Decoder, Encoder-এর কাছ থেকে source sentence-এর information নেয়।

SELF-ATTENTION vs CROSS-ATTENTION — Q, K, V-এর পার্থক্য: ════════════════════════════════════════════════════════════════ ┌─────────────────────────────────────────────────────────┐ │ SELF-ATTENTION (Encoder বা Masked) │ │ │ │ Query (Q) ──┐ │ │ Key (K) ──┼──→ সবই একই জায়গা থেকে আসে │ │ Value (V) ──┘ (নিজের embedding থেকে) │ └─────────────────────────────────────────────────────────┘ ┌─────────────────────────────────────────────────────────┐ │ CROSS-ATTENTION │ │ │ │ Query (Q) ──→ DECODER থেকে আসে │ │ "আমি এখন এখানে আছি, কী দরকার?" │ │ │ │ Key (K) ──→ ENCODER থেকে আসে │ │ Value (V) ──→ ENCODER থেকে আসে │ │ "আমার কাছে source-এর পুরো অর্থ আছে" │ └─────────────────────────────────────────────────────────┘ উদাহরণ (বই অনুবাদ): Masked Self-Attention = নিজের বাংলা খাতা পড়ে পরের শব্দ ভাবা Cross-Attention = মূল ইংরেজি বই দেখে মিলিয়ে নেওয়া
