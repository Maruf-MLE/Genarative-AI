সহজ ভাষায় পরিচিতি — Inference কী এবং কেন আলাদা?

Section 1 · Intuition & Problem Definition
📌 মূল প্রশ্ন

আমরা এতদিন Transformer Architecture পড়েছি — কিন্তু সেটা ছিল Training-এর সময়কার আচরণ। আজ আমরা জানব, একবার মডেল ট্রেন হয়ে গেলে, Inference বা Prediction-এর সময় কী ঘটে।

রান্নাঘরের উদাহরণ দিয়ে বোঝা যাক

ধরো তুমি একটি রেস্তোরাঁর রাঁধুনি। তুমি বছরের পর বছর ধরে রান্না শিখেছ (= Training)। এখন একজন customer এসে বলল, "একটি বিরিয়ানি বানিয়ে দাও।" তুমি তখন কি করো? তুমি কি একসাথে সব স্টেপ করো? না! তুমি প্রথমে চাল সিদ্ধ করো, তারপর মশলা যোগ করো, তারপর মাংস দাও — একটার পর একটা ধাপে। এটাই হলো Inference — যেখানে একটু একটু করে আউটপুট তৈরি হয়।

🏋️

Training সময় (Non-auto-regressive)

ট্রেনিং-এ Decoder একসাথে সব output token পায়। মানে, "হম দোস্ত হ্যায়" — এই পুরো বাক্যটা Decoder-এ একসাথে ঢুকে। কারণ ট্রেনিং ডেটায় উত্তর আগে থেকেই জানা।

🔮

Inference সময় (Auto-regressive)

Inference-এ আমরা জানি না output কী হবে। তাই Decoder একটি একটি করে token তৈরি করে — প্রতিটি নতুন token আগেরটার উপর নির্ভর করে। এটাই Auto-regressive পদ্ধতি।

💡 সবচেয়ে বড় পার্থক্য

Encoder: Training এবং Inference — দুই সময়ে একই রকম আচরণ করে। কোনো পার্থক্য নেই।

Decoder: Training-এ Non-auto-regressive (সব token একসাথে), কিন্তু Inference-এ Auto-regressive (একটার পর একটা)। এটাই আজকের আলোচনার মূল বিষয়।

⚙️

Setup এবং পূর্বপ্রস্তুতি

Section 2 · Problem Setup

এই গাইডে আমরা একটি নির্দিষ্ট উদাহরণ দিয়ে পুরো Inference প্রক্রিয়া বুঝব। সেটআপ হলো একটি Machine Translation Task।

1

ট্রেনিং সম্পন্ন

উপরের ডেটাসেটের উপর Transformer Architecture ট্রেন করা হয়েছে। সমস্ত Weights এবং Biases-এর সঠিক মান পাওয়া গেছে। মডেল এখন Prediction করতে প্রস্তুত।

2

Query Sentence

এখন আমরা মডেলকে প্রশ্ন করব: "We are friends" — এই ইংরেজি বাক্যের হিন্দি অনুবাদ কী? মডেলকে এর উত্তর বের করতে হবে।

3

আর্কিটেকচার: 6 Encoder + 6 Decoder

ক্লাসিক Transformer Architecture-এ ৬টি Encoder Block এবং ৬টি Decoder Block থাকে। প্রতিটি Block-এ একই ধরনের অপারেশন হয়, তবে আলাদা Parameter Values দিয়ে।

Encoder-এর ভূমিকা এবং সম্পূর্ণ প্রক্রিয়া

Decoder Inference — ধাপে ধাপে বিস্তারিত বিশ্লেষণ

Section 4 · Decoder Architecture During Inference

Decoder-এর ভেতরে তিনটি প্রধান Block আছে। Inference-এ এগুলো কীভাবে কাজ করে — একটু একটু করে বুঝব। প্রথমে Time Step 1 দিয়ে শুরু করা যাক।

🚀 শুরু হয় একটি বিশেষ Token দিয়ে

Decoder-এর প্রক্রিয়া শুরু করতে একটি বিশেষ Token ব্যবহার করা হয়: SOS (Start Of Sentence)। এই Token দেখলেই Decoder বুঝে যায় যে তার কাজ শুরু করার সময় এসেছে।

Decoder-এর ভেতরের তিনটি Block

1

Block 1: Masked Self-Attention

Decoder-এর নিজের sequence-এর মধ্যে attention। "Masked" কারণ ভবিষ্যতের token দেখা যায় না। এখানে Decoder নিজের তৈরি করা token গুলোর মধ্যে সম্পর্ক বোঝে।

2

Block 2: Cross-Attention

Encoder-এর output এবং Decoder-এর output-এর মধ্যে attention। Decoder এখানে Encoder-এর context ব্যবহার করে জানতে পারে — "আমি এখন যে output দিচ্ছি, তা input-এর কোন অংশের সাথে বেশি সম্পর্কিত?"

3

Block 3: Feed Forward Neural Network

Non-linear transformation করে (512→2048→512)। এটি vector-এর মধ্যে complex patterns capture করে। একই আর্কিটেকচার Encoder-এর মতোই।

Time Step 1: SOS Token → প্রথম আউটপুট শব্দ

🎯 Cross-Attention: সবচেয়ে গুরুত্বপূর্ণ অংশ

Cross-Attention হলো Transformer-এর হৃদয়। এখানে Decoder বলছে: "আমি এখন SOS দেখছি — Encoder যে ইংরেজি বুঝেছে (We, are, friends) তার কোন অংশের সাথে SOS সবচেয়ে বেশি সম্পর্কিত? সেই অনুযায়ী আমি পরবর্তী হিন্দি শব্দ বেছে নেব।"

Linear + Softmax: কীভাবে আউটপুট শব্দ বের হয়?

▶ VOCABULARY PROBABILITY DISTRIBUTION
yf1_norm (512-dim vector) ↓ Linear Layer: W matrix = (512 × |V|) ↓ logits = yf1_norm × W = [3.2, -1.4, 0.8, 5.7, -2.1, ...] ← raw unnormalized scores ^হম ^আপ ^বো ^মৈ ... ↓ softmax probabilities = softmax(logits) = [0.87, 0.02, 0.01, 0.05, 0.003, ...] ← sum = 1.0 ↓ argmax OUTPUT = "হম" (probability = 0.87, সর্বোচ্চ)

Auto-regressive Loop — সম্পূর্ণ Time Step বিশ্লেষণ

Section 5 · Step-by-Step Token Generation

এখানেই আসল মজার ব্যাপার! Auto-regressive মানে হলো — প্রতিটি পদক্ষেপে আগের সব token-কে input হিসেবে ব্যবহার করে নতুন token তৈরি করা।

⚡ Auto-regressive নিয়ম

Time Step N-এ, Decoder-এর input হবে: [SOS, token_1, token_2, ..., token_(N-1)]
এবং output হবে: token_N

প্রতি পদক্ষেপে input একটি করে বাড়তে থাকে।

Embedding Layer → ১টি vector (X1)
Masked Self-Attention → SOS নিজের সাথে similarity
Cross-Attention → SOS vs (We, are, friends)
Output: Probability distribution over Hindi vocabulary

EOS token পাওয়া মাত্রই Inference প্রক্রিয়া থামে। Final Output: "হম দোস্ত হ্যায়"

একটি গুরুত্বপূর্ণ ট্রিক: শুধু শেষের Vector পাঠানো হয়

🔑 Critical Point — সবচেয়ে গুরুত্বপূর্ণ বিষয়

প্রতিটি Time Step-এ Decoder সব token-এর vectors নিয়ে কাজ করে — কিন্তু Linear + Softmax layer-এ শুধু সবচেয়ে শেষের token-এর vector পাঠানো হয়।

উদাহরণ: Time Step 2-এ input হলো [SOS, হম]। Decoder দুটি vector তৈরি করে। কিন্তু output-এর জন্য শুধু "হম"-এর vector পাঠানো হয়। "SOS"-এর vector ignore করা হয় — কারণ SOS-এর output (হম) আগেই বের হয়ে গেছে।

Auto-regressive নিয়ম: প্রতি Time Step-এ শুধু একটি নতুন token output হবে।

▶ কোন Vector কোথায় যায় — Time Step 2
Input: [SOS, হম] ↓ 6 Decoder Blocks processing ↓ After processing, we have 2 vectors: yf1_norm ← SOS-এর কথার vector yf2_norm ← হম-এর কথার vector ↓ Output-এর জন্য: yf1_norm ✗ IGNORED (SOS-এর output "হম" আগেই পেয়েছি) yf2_norm ✓ → Linear Layer → Softmax → Output = "দোস্ত" RULE: Always use ONLY the last token's vector for output!

Masking — Inference-এও কেন প্রয়োজন?

Section 6 · Causal Masking in Inference
⚠️ সাধারণ ভুল ধারণা

অনেকে মনে করেন: "Inference-এ masking লাগবে না, কারণ আমরা তো জানি কোন token কখন এসেছে।" — এটি সম্পূর্ণ ভুল। Inference-এ masking অবশ্যই প্রয়োজন।

Masking কী এবং কীভাবে কাজ করে?

Masked Self-Attention-এ, প্রতিটি token শুধু নিজের আগের token গুলোকে দেখতে পারে। ভবিষ্যতের token দেখা নিষিদ্ধ। এটি একটি Causal Masking — অর্থাৎ "যা আগে ঘটেছে শুধু তা দেখা যাবে।"

▶ MASKING MATRIX — [SOS, হম, দোস্ত] এর ক্ষেত্রে
Attention Score Matrix (before masking): SOS হম দোস্ত SOS [ 0.8 0.3 0.5 ] হম [ 0.6 0.7 0.4 ] দোস্ত [ 0.4 0.5 0.9 ] Apply Upper Triangle Masking (future positions → -∞): SOS হম দোস্ত SOS [ 0.8 -∞ -∞ ] ← SOS শুধু নিজেকে দেখে হম [ 0.6 0.7 -∞ ] ← হম দেখে: SOS + হম দোস্ত [ 0.4 0.5 0.9 ] ← দোস্ত দেখে: সবাইকে After softmax (−∞ becomes 0): SOS হম দোস্ত SOS [ 1.00 0.00 0.00 ] হম [ 0.46 0.54 0.00 ] দোস্ত [ 0.23 0.29 0.48 ]

Inference-এ Masking কেন প্রয়োজন?

🎓

Training Consistency

Training-এ আমরা Masking ব্যবহার করেছিলাম। Machine Learning-এর মূল নিয়ম: Training-এ যা করেছ, Inference-এ সেটাই করো। নইলে Distribution Shift হয় এবং মডেলের মান কমে যায়।

🔄

Causal Property

এমনকি যদি আমরা জানিও যে "হম" আগে এসেছে — তবুও "SOS"-কে "হম" দেখতে দেওয়া ঠিক নয়। কারণ Training-এ এটা হতো না। Model-এর decision process-এ consistency বজায় রাখতে Masking লাগে।

📐 সহজ নিয়ম

পুরো Machine Learning-এ একটাই মূলনীতি: "Training ডেটায় যা করো, Inference ডেটায়ও সেটাই করো।" Training-এ Masking ছিল, তাই Inference-এও Masking থাকবে।

Cross-Attention Mechanism — বিস্তারিত Flow

▶ CROSS-ATTENTION FLOW — Time Step 2 (SOS + হম)
FROM ENCODER: FROM DECODER (after Masked Self-Attn): V_we (512-dim) z1_norm ← SOS-এর vector V_are (512-dim) z2_norm ← হম-এর vector V_fri (512-dim) │ │ ↓ ↓ Key Extraction: Query Extraction: K_we = V_we · Wk Q_sos = z1_norm · Wq K_are = V_are · Wk Q_hum = z2_norm · Wq K_fri = V_fri · Wk Value Extraction: Val_we = V_we · Wv Val_are = V_are · Wv Val_fri = V_fri · Wv Similarity Calculation (Q × K^T): V_we V_are V_fri SOS [ w11 w12 w13 ] ← SOS vs (We, are, friends) হম [ w21 w22 w23 ] ← হম vs (We, are, friends) Scale by 1/√512, then Softmax → attention weights Output for SOS: zc1 = w11·Val_we + w12·Val_are + w13·Val_fri Output for হম: zc2 = w21·Val_we + w22·Val_are + w23·Val_fri → Final: Use zc2 (last token) for output prediction = "দোস্ত"

Masking Pattern — Inference সময়কার Matrix

▶ MASKING PATTERN FOR EACH TIME STEP
Time Step 1: Input=[SOS] Mask: SOS SOS [ 1 ] Time Step 2: Input=[SOS, হম] Mask: SOS হম SOS [ 1 0 ] ← SOS cannot see হম (future) হম [ 1 1 ] ← হম can see SOS and itself Time Step 3: Input=[SOS, হম, দোস্ত] Mask: SOS হম দোস্ত SOS [ 1 0 0 ] হম [ 1 1 0 ] দোস্ত [ 1 1 1 ] Time Step 4: Input=[SOS, হম, দোস্ত, হ্যায়] Mask: SOS হম দোস্ত হ্যায় SOS [ 1 0 0 0 ] হম [ 1 1 0 0 ] দোস্ত [ 1 1 1 0 ] হ্যায় [ 1 1 1 1 ] PATTERN: Lower triangular matrix (1=attend, 0=masked)

Section 8 · Key Takeaways

🏆 Training vs Inference — মূল পার্থক্য

বিষয় Training Inference
Encoder আচরণ একই রকম ✓ একই রকম ✓
Decoder আচরণ Non-auto-regressive Auto-regressive
Decoder Input সব output token একসাথে Token একটি একটি করে
Output generation একবারে সব token একটি করে, একাধিক step-এ
Masking হ্যাঁ, আবশ্যক হ্যাঁ, আবশ্যক (same as training)
শুরু হয় সব token দিয়ে SOS token দিয়ে
শেষ হয় Loss calculation-এ EOS token পেলে
Speed Parallel (দ্রুত) Sequential (ধীর)

🔑 সবচেয়ে গুরুত্বপূর্ণ ৬টি পয়েন্ট

Encoder: Training = Inference — Encoder-এর আচরণ কখনো বদলায় না। Training এবং Inference — দুই সময়ে সম্পূর্ণ একই পদ্ধতিতে কাজ করে।
Decoder: Auto-regressive in Inference — Inference-এ Decoder একটি একটি করে token তৈরি করে। প্রতিটি নতুন token আগের সব token-কে input হিসেবে নেয়।
SOS দিয়ে শুরু, EOS-এ শেষ — Decoder সবসময় SOS (Start Of Sentence) token দিয়ে শুরু হয় এবং EOS (End Of Sentence) token পেলে থামে।
প্রতি Step-এ Input বাড়ে — Step 1: [SOS], Step 2: [SOS, t1], Step 3: [SOS, t1, t2], ... এভাবে প্রতিটি পদক্ষেপে input একটি করে বাড়তে থাকে।
শেষ Vector-ই Output-এ যায় — প্রতিটি Time Step-এ Decoder সব token-এর vectors নিয়ে কাজ করলেও, Linear+Softmax layer-এ শুধু সবচেয়ে শেষের token-এর vector পাঠানো হয়।
Masking Inference-এও থাকে — Training Consistency বজায় রাখতে Inference-এও Causal Masking প্রয়োজন। "আমি তো জানি কোন token আগে এসেছে" — এই যুক্তিতে Masking বাদ দেওয়া যাবে না।
